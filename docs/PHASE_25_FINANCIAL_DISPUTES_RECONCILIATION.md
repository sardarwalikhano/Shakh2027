# SHAKH 2027 — Phase 25: Financial Disputes + Reconciliation

Phase 25 is an additive finance hardening layer. Existing wallet, payment, refund, payout, COD, captain earning, order and audit behavior is preserved.

## Backend

- Extended `refunds` with provider references, failure metadata, `payment_transaction_id`, and update auditing.
- Added `financial_disputes` for chargebacks, payment disputes, refund disputes, cash disputes, payout disputes and order disputes.
- Added server-side dispute state machine: `open -> in_review -> accepted/rejected/resolved/cancelled`, and `accepted -> resolved`.
- Added idempotency protection for dispute creation and provider case references.
- Added RLS so users can read their own disputes while finance can read the finance queue.
- Public RPC wrappers are `SECURITY INVOKER`; privileged implementation functions remain private `SECURITY DEFINER` with pinned search paths.
- Added finance reconciliation anomalies for refund/ledger mismatches, captain earning linkage, withdrawal/payout state, and succeeded payment vs unpaid order state.
- Extended payment transaction types with `chargeback` without inventing a provider API.

## Frontend

Finance Center now exposes:

- dispute/chargeback queue and server-authoritative status transitions,
- reconciliation anomaly visibility,
- dispute creation against a real order ID,
- existing captain earning and COD reconciliation controls.

No provider credential or fake payment reference is generated by SHAKH.
